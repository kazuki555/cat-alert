# 猫アラート v5

iPhone（B）のカメラに動物が映ったら、もう1台のiPhone（A）に知らせる仕組みです。
v5からは、**AでBのライブ映像を見ながら**、Aから「カメラ切替」「ライト」「低光量モード」を操作できます。
映っている間だけ録画して、B本体に保存することもできます。

```
[B: カメラ側 iPhone / Safari]                         [A: 見る側 iPhone / Safari ＋ ntfyアプリ]
 カメラ映像 ──ライブ映像（直接）──────────────────→  映像を表示（枠つき）
 AIが動物を判定 ── 知らせ（帯と音）────────────────→  画面に帯＋音＋写真つき記録
                └─ ntfy.sh ───────────────────────→  ntfyアプリに写真つき通知
 ←─ 操作：カメラ切替／ライト／低光量モード ───────────
 （BはAのインターネット共有でネットにつながる）
```

- 判定はB本体の中で行います。
- **ライブ映像は、AとBの間で直接やりとりします**（外部のサーバーには保存しません）。相手を探すときだけ、無料のサーバー（PeerJS）を使います。
- 通知の写真は、ntfy.sh を通ります（通知するときの写真1枚だけ）。
- **見つける動物**：猫・犬・鳥・馬・羊・牛・象・クマ・シマウマ・キリン。タヌキなどは、猫や犬と見まちがえて見つけることがあります。「人」も選べます。
- **録画**：見つけてから映らなくなるまでの間だけ録画し、B本体に保存します。Aの「カメラ側の録画」欄で「見る」を押すと、Bから受け取って再生できます（ライブ映像につながっているときだけ。通知には付きません）。Bの「録画」欄から、再生や、写真アプリへの保存、AirDropもできます。
- 費用はかかりません（無料の通知サービス ntfy と、無料の公開場所 GitHub Pages、無料の相手探しサーバー PeerJS を使います）。
- 必要なのは、ページを開くSafari（AとB）と、無料アプリ「ntfy」（A）だけです。

---

## 必要なもの

| もの | 内容 |
|---|---|
| A（見る側・通知を受ける） | iPhone。回線あり。インターネット共有（テザリング）をオンにする |
| B（カメラ側） | iPhone。iOS 16.4以降がおすすめ |
| 充電ケーブル | Bは見張りの間ずっと充電する。Aも長時間なら充電する |
| GitHubアカウント | ページを公開するために使う（無料） |

---

## 手順1：ページを公開する（パソコンで1回だけ）

カメラを使うページは、`https://` で始まるアドレスで開く必要があります。GitHub Pages（無料）で公開します。

1. https://github.com でアカウントを作ります（作成は自分で行ってください）。
2. 右上の「＋」→「New repository」を選びます。
   - Repository name：`cat-alert`（好きな名前でかまいません）
   - 「Public」を選んで「Create repository」を押します。
3. 次の画面の「uploading an existing file」をクリックし、このフォルダの **`index.html` と `js` フォルダ**（中の `common.js`・`camera.js`・`link.js`・`viewer.js`）をドラッグして「Commit changes」を押します。`test` フォルダは、パソコンでのテスト用なので、上げなくてかまいません。
4. リポジトリの「Settings」→ 左のメニューの「Pages」を開きます。
   - 「Build and deployment」の Source を「Deploy from a branch」にします。
   - Branch を「main」、フォルダを「/ (root)」にして「Save」を押します。
5. 1〜2分待つと、同じ画面の上に `https://<ユーザー名>.github.io/cat-alert/` と表示されます。**これがBで開くアドレス**です。

> `index.html` と `js` フォルダの中に、合言葉（トピック名）などの秘密の情報は入っていません。合言葉は、それぞれのiPhoneの中だけに保存されます。そのため、リポジトリを公開（Public）にしても問題ありません。

## 手順2：Aでインターネット共有をオンにする

1. 「設定」→「インターネット共有」で「ほかの人の接続を許可」をオンにし、Wi-Fiのパスワードを確認します。
2. 同じ画面に「互換性を優先」があればオンにします（2.4GHzになり、遠くまで届きやすくなります）。
3. 「設定」→「バッテリー」で「低電力モード」をオフにします（オンだとインターネット共有が切れることがあります）。

## 手順3：BをAにつなぎ、ページを開く

1. Bの「設定」→「Wi-Fi」で、Aのネットワークを選んで接続します。
2. BのSafariで、手順1のアドレスを開きます。
   - **プライベートブラウズでは開かないでください**（設定を保存できません）。
   - 開いたら、ブックマークしておくと次から楽です。
3. 最初に出る画面で「📷 カメラにする（B）」を選びます。あとから、「設定」の「役割を変える」で選び直せます。
4. 「設定」欄に表示される**トピック名**（`neko-` から始まる文字列）が、通知と映像の合言葉です。
   - 「共有」ボタンを押すと、**見る側（A）の招待リンク**を、AirDropやメッセージでAに送れます（手順5で使います）。
   - トピック名は、紙などにも控えておいてください（後で説明するように、消えることがあります）。

## 手順4：Aにntfyアプリを入れて購読する

1. AのApp Storeで「ntfy」を探して入れます（無料）。
2. ntfyアプリの「＋」から、Bのトピック名を入力して購読（Subscribe）します。サーバーは最初から入っている ntfy.sh のままにします。
3. 通知の許可を求められたら「許可」します。
4. おやすみモードなどの集中モード中でも鳴らしたい場合は、「設定」→「集中モード」→ 使うモード →「通知を許可」で、ntfy を許可するアプリに加えます。

## 手順5：Aでライブ映像を見る

1. Bで「見張りを始める」を押します（カメラの使用を「許可」します）。
2. Bの「共有」で送った招待リンクを、Aで開きます（Safari）。自動で役割が「見る側」になり、合言葉が入ります。
   - リンクを使わないときは、Aでページを開いて「👀 見る側にする（A）」を選び、「設定」の「合言葉」にBのトピック名を入力します。
3. 「見る」を押します。10秒ほどで、Bの映像が出ます。
   - 「接続の種類」に「直接つながっています」と出ていれば、AのデータとBのデータ通信量はかかりません。「中継サーバー経由です」と出たときは、Aのデータ通信量を使います（1時間で数百MBになることがあります）。
4. 映像の下の3つのボタンで、Bを操作できます。
   - **🔄 カメラ切替**：Bのインカメ／外カメを切り替えます。映像はつなぎ直さずに、そのまま続きます。
   - **🔦 ライト**：Bのフラッシュライトをつけたり消したりします。外カメのとき、しかも端末が対応しているとき（iOS 17.5ごろ以降）だけ使えます。使えないときは、ボタンが薄くなり、理由が出ます。
   - **🌙 低光量**：自動／オン／オフを順に切り替えます。暗い映像を、Aの画面で明るく見せます（Bは熱くなりません）。オンのときは、Bのカメラのコマ数を下げて、少し明るく撮ります。
   - Bの画面のボタン（「カメラ切替」「ライト」、設定の「低光量モード」）でも、同じことができます。
5. 動物が来ると、Aの画面の上に大きな帯（例：「🐾 動物が来ました（猫）」）が出て、音が鳴り、写真つきで記録に残ります。映像の上には、AIが見つけた場所の枠が出ます（実線は通知の基準を超えたもの、点線は届かないもの）。
   - 音を鳴らすために、最初に「見る」を押す必要があります（iPhoneの決まり）。
6. 「全画面」で、映像を大きくできます。「やめる」で、見るのをやめます。
7. 同時に見られるのは**2人まで**です。3人目は「いま見ている人が多いので見られません」と出ます。
8. Aの画面を消したり、Safariを閉じたりすると、映像は止まります。**ただし、ntfyアプリへの通知は、今までどおり届きます。**

## 手順6：動作確認

1. Bで「テスト通知」を押します → 数秒でAに「テスト通知」が写真付きで届けばOKです。
2. Bで「見張りを始める」を押します → カメラの使用を「許可」します。
3. 猫の写真をパソコンや別のスマホの画面に出して、Bのカメラに見せます → 数秒でAのntfyアプリに「動物が来ました（猫・◯%）」と届けばOKです。Aでライブ映像を見ているときは、帯と音も出ます。
4. 猫を見せている間、状態表示の「録画」欄が「● 録画中」になります。写真を隠して5秒たつと録画が止まり、Bの「録画」欄に1本増えていればOKです。「再生」で中身を確かめられます。
5. 写真を隠したまま待つと、状態表示の「判定」欄に「見えなくなって◯秒（あと◯秒で『いない』に戻ります）」と出ます。60秒たって「いない」に戻ってから、もう一度見せると、また通知されます。
   - **60秒以内に見せ直しても通知は来ません**（同じ猫がまだいるとみなすため）。
   - テストを早く進めたいときは、設定の「『いなくなった』とみなすまで」と「同じ対象の通知の最短間隔」を両方30秒にしてください。

## 手順7：長時間見張るためのBの設定

| 設定 | 場所 | 理由 |
|---|---|---|
| 自動ロック「なし」 | 設定 → 画面表示と明るさ → 自動ロック | 画面が消えると見張りが止まるため |
| カメラを「許可」に固定 | Safariでページを開いた状態で、アドレス欄の「ぁあ」などのメニュー →「Webサイトの設定」→ カメラ →「許可」 | ページが読み込み直されたときに、確認なしで自動再開できるようにするため |
| 集中モード（おやすみモード） | コントロールセンター | 着信や通知で画面が切り替わらないようにするため |
| 低電力モード「オフ」 | 設定 → バッテリー | 動きが制限されないようにするため |
| アクセスガイド | 設定 → アクセシビリティ → アクセスガイド をオンにし、パスコードを決める。Safariで見張りを始めたら、サイドボタン（ホームボタンがある機種はホームボタン）を3回押して「開始」 | 誤ってSafariを閉じたり、ほかの画面に移ったりするのを防ぐため。終わるときは3回押してパスコードを入力 |
| 明るさを最小に | コントロールセンター | 発熱と電池を抑えるため。「省電力表示」ボタンで画面を黒くするとさらに効果的（すばやく2回タップで戻ります） |

## 置き方のコツ

- **充電しながら**使います。直射日光や暑い場所は避けます（iPhoneが熱くなりすぎるとカメラが止まります）。
- 猫が通る場所が、**画面の1割くらい以上の大きさ**で映る距離に置きます。遠くて小さいと見逃しやすくなります。
- 「見張る範囲」を指定すると、その部分だけを拡大して判定するので、小さな猫も見つけやすくなります。範囲の外の動きにも反応しなくなります。
- **暗いと見つけにくくなります。** 設定の「低光量モード」（初期設定は「自動」）が、暗い映像を明るくして判定・通知の写真・録画に使いますが、真っ暗な場所までは補正できません。夜も使うなら、外灯やセンサーライトで照らします。室内から窓越しに撮るときは、部屋の明かりがガラスに映り込まないよう、窓の近くの明かりを消すか、カメラをガラスに近づけます。
- **人を対象にするとき**は、通行人や隣の家が映らない向きに置いてください。
- AとBが離れすぎるとインターネット共有が届きません。家の中なら十数mが目安です。置き場所で「テスト通知」が届くか、必ず確かめてください。

## 設定項目

| 項目 | 最初の値 | 説明 |
|---|---|---|
| トピック名 | 自動で作成 | 通知の合言葉。Aのntfyアプリで同じ名前を購読する |
| 見つける対象 | 動物（ぜんぶ） | 「動物」（猫・犬・鳥・馬・羊・牛・象・クマ・シマウマ・キリン）と「人」から選ぶ（両方も選べる） |
| 判定の厳しさ | 50%以上 | 上げると間違いの通知が減り、見逃しが増える。映像の枠に出る%を見て調整する |
| AIモデル | 標準 | 「高精度」は少し重いが、小さい・遠い対象に強い |
| 1秒あたりの判定回数 | 3回 | 減らすと電池と発熱を抑えられる |
| 「いなくなった」とみなすまで | 60秒 | この時間映らなければ「いない」に戻り、次に現れたらまた通知する |
| 同じ対象の通知の最短間隔 | 60秒 | 出たり入ったりしたときの連続通知を防ぐ |
| 画角（映る範囲） | 標準（4:3） | 4:3は標準のカメラアプリの写真と同じ広さ。「超広角」は、超広角カメラのあるiPhone（iPhone 11以降の多く）で、もっと広く映せる。「16:9」は以前の設定で、上下が切れて狭くなる |
| 低光量モード | 自動 | 暗い場所で映像を明るくする。「自動」は暗いときだけ、「オン」はいつも強く明るくする（コマ数も下げる）、「オフ」は何もしない。見る側のボタンからも切り替えられる |
| 見張る範囲 | 画面全体 | 映像の上を指でなぞって指定する |
| 映り続けているときの通知 | 1分ごと | 動物が映り続けている間、この間隔で「動物がまだいます（猫・◯分◯秒）」と写真つきで通知する。「しない」にすると、来たときの1回だけになる |
| 見つけている間だけ録画する | オン | 見つけたら録画を始め、映らなくなったら止めてB本体に保存する |
| 映らなくなってから止めるまで | 5秒 | 猫と判定されなくなってから録画を止めるまでの時間。一瞬見えなくなっただけで録画が切れないようにするための待ち時間 |
| GPUを使う（詳細設定） | オフ | 試験的な機能。速くなることがあるが、動きが不安定なら外す |
| 通知サーバー（詳細設定） | https://ntfy.sh | 通常は変えない |

判定のしくみ：直近5回の判定のうち3回以上で見つかると「来た」と判断し、まず「動物が来ました（猫・◯%）」と通知します。そのまま映り続けているあいだは、設定の「映り続けているときの通知」（初期設定は1分ごと）の間隔で「動物がまだいます（猫・◯分◯秒）」と通知し続けます。「来た／いない」は、動物（ぜんぶ）でひとまとめに判断します。状態表示の「判定」欄に、次の通知までの残り秒数が出ます。
いったん見えなくなっても、「いなくなった」とみなすまでの時間（初期設定は60秒）のうちに戻ってきた場合は、同じ猫がまだいるとみなし、通知しません。状態表示の「判定」欄で、「いない」に戻るまでの残り時間を確認できます。

## 困ったとき

| 症状 | 確認すること |
|---|---|
| 通知が来ない | AとBのトピック名が完全に同じか／Aでntfyの通知が許可されているか／Bの「通信」欄が「正常」か／Aが集中モードになっていないか |
| 「カメラを起動できませんでした」と出る | Safariでこのサイトのカメラが「許可」になっているか／アドレスが https:// で始まっているか |
| 猫がいるのに反応しない | 判定の厳しさを下げる／見張る範囲を猫が通る場所に絞る／明るくする／近づける／AIモデルを「高精度」にする |
| 映像が標準のカメラアプリより暗い | Safariのカメラは、標準カメラアプリのような自動の明るさ調整（HDR・夜景モードなど）が使えないため、暗めに映ります。設定の「低光量モード」が「自動」か「オン」になっているか確認してください。それでも暗いときは、照明を足すのがいちばん効きます |
| 動物ではないもの（置物など）で通知が来る | 判定の厳しさを上げる／見張る範囲を絞る |
| 見張りが勝手に止まる | 自動ロック「なし」・低電力モード「オフ」・アクセスガイド・充電を確認する |
| インターネット共有が切れる | Aの低電力モードをオフにする／Aの「互換性を優先」をオンにする／AとBを近づける |
| 映り続けているのに通知が来ない | 設定の「映り続けているときの通知」が「しない」になっていないか／「判定」欄の「次の通知まで あと◯秒」を確認／今日の通知が170通を超えていないか（超えると、映り続けているあいだの通知は止まります） |
| 2回目の通知が来ない | 状態表示の「判定」欄を見てください。「見えなくなって◯秒（あと◯秒で…）」と出ている間は、同じ猫がまだいるとみなすので通知しません。「いない（次に通知できるまで あと◯秒）」と出ている間も通知しません。テストのときは、設定の「『いなくなった』とみなすまで」と「同じ対象の通知の最短間隔」を両方30秒にすると早く試せます |
| トピック名（合言葉）が変わってしまった | 次のような場合は、Bに保存していた合言葉が消えて、新しい合言葉が自動で作られます：Safariで「履歴とWebサイトデータを消去」をした／プライベートブラウズで開いた／長い間（7日以上など）このページを開かなかった／ホーム画面のアイコンから開いた（Safariとは保存場所が別）。控えておいた合言葉を「トピック名」欄に入力し直せば、Aの設定はそのままで届くようになります |
| 録画が保存されない | 設定の「見つけている間だけ録画する」がオンか／状態表示の「録画」欄が「非対応」になっていないか／Bの空き容量が足りているか |
| Aに映像が出ない（「カメラが見つかりません」） | Bで「見張りを始める」を押しているか／AとBの合言葉（トピック名）が同じか／Bの「見ている人」欄や記録に「映像をつなぐサーバーにつながりません」と出ていないか。Bを読み込み直した直後は、しばらく（最大2分）つながらないことがあります。Aは自動で試し続けます |
| 「合言葉が違います」と出る | Bの合言葉を変えたあとに、Aが古いままのときなど。Aの「設定」の「合言葉」を直すか、Bの招待リンクをもう一度開いてください |
| 「映像をつなぐサーバーにつながりません」 | PeerJSの無料サーバー（0.peerjs.com）が止まっているか、ネットにつながっていません。判定・ntfy通知・録画は、そのまま動きます。しばらくして、つなぎ直されるのを待ってください |
| 「中継サーバー経由です」と出る | AのデータとBの間が直接つながらず、中継を通っています。Aのデータ通信量を使います（Bは画質を下げて送ります）。AとBを近づけて、Bで「見張りを始める」をやり直してみてください |
| ライトのボタンが薄い | 理由が映像の下に出ます。「外カメのときだけ」ならカメラ切替で外カメに。「この端末ではライトを操作できません」は、iOSが古い（17.5ごろより前）などで、使えません |
| Aで音が鳴らない | 最初に「見る」を押したか／Aの消音スイッチ（サイレント）がオフか／音量を確認してください |
| 録画を写真アプリに残したい | 「録画」欄の「保存・共有」→「ビデオを保存」を選ぶ。Aに送るときは同じ画面でAirDropを選ぶ |

「記録」欄に、検知・送信・エラーの履歴が出ます（写真をタップすると大きく表示されます）。

## 注意点と、できないこと

- **Bが止まっても、Aには知らせが届かないことがあります。** たとえばBの電池切れや、Safariが閉じられた場合です。ただし次の場合は通知が届きます。
  - 見張りを始めたとき・再開したとき：「見張りを始めました／再開しました」
  - ページが読み込み直されたあと、自動で再開できなかったとき：「見張りを再開できませんでした」
- **Aを持って出かけると、Bはネットにつながらず通知できません。** Aが戻ってくると、Bは自動でつなぎ直し、送れなかった通知を送り直します（最大5件まで）。
- 写真は、公開の通知サーバー（ntfy.sh）を通ります。トピック名を知っている人は通知を見られるので、他人には教えないでください。ntfy.shに送った写真は3時間で自動的に消えます。
- ntfy.sh を無料で使えるのは1日250通までです。このアプリは、1日200通で送信を止めます。
  - 「映り続けているときの通知」を1分ごとにすると、猫が映り続けた場合は1時間で60通になり、**約2時間半（1日170通）で、映り続けているあいだの通知が止まります**。残りの30通は、新しく来たときの通知のために残してあります。
  - 通知が多すぎるときは、「3分ごと」や「10分ごと」に変えてください。ntfyの有料プランにすると、上限が増えます。
  - 「まだいます」の写真は、無料枠の添付の合計（20MB・3時間で自動削除）を使い切らないよう、小さめ（幅480px）で送ります。写真つきで送れなかったときは、文字だけで送り直します。
- 見張りの間は、BのSafariを開いたまま、画面をつけたままにする必要があります（iPhoneの決まりで、裏で動かしたままにはできません）。
- 録画について：
  - 録画は**B本体の中**に保存します。無料の通知サービスでは添付ファイルが1つ2MBまでで、動画はすぐにこれを超えるため、ntfyの通知には付けません。そのかわり、Aがライブ映像につながっているときは、Aの画面から直接Bに頼んで受け取れます。
  - 見つけてから録画が始まるまで1秒ほどかかるので、現れた瞬間は映っていないことがあります。
  - 1本は最長5分です（それより長く映っているときは、続きを新しい1本として録ります）。合計300MBか50本を超えると、古いものから自動で消えます。画質は約1Mbpsで、1分あたり約7.5MBです。
  - 録画している途中でページが落ちたり、Safariが閉じられたりすると、その録画は保存されません。
  - Safariの保存データは、長い間（7日以上など）サイトを開かないと消えることがあります。残したい録画は、写真アプリに保存してください。
  - 録画中は処理が増えるので、iPhoneが熱くなりやすくなります。
  - 明るさ補正がオン（初期設定）のときは、補正したあとの映像を録画します。そのため録画の解像度は最大幅960px、コマ数は1秒15回になり、補正を「なし」にしたときより少し画質が下がります。
- 夜の真っ暗な場所には対応していません（低光量モードは、形が見えるようにする程度です）。
- 次のことは、できません：
  - 音声（マイク）を届けること、Aから話しかけること
  - Bに保存した録画を、Aで見ること（B本体から、AirDropなどで送ります）
  - 外出先から見ること（Aを持って出かけると、Bはネットにつながりません）
- ライブ映像のあいだは、Bが「判定＋映像の送信＋録画」を同時に行うので、熱くなりやすくなります。見る人がいないときは、映像を送りません。

## 技術メモ

- 判定：MediaPipe Tasks Vision 1.0.1 の Object Detector（EfficientDet-Lite0／Lite2、COCOデータセットで学習済み）。WebAssemblyで、B本体の中で動きます。
- 通知：`PUT https://ntfy.sh/<トピック名>?title=…&message=…&tags=cat&priority=4&filename=….jpg`（本文がJPEG写真）。日本語はURLのパラメータで渡しています。
- 保存：設定はSafariの localStorage に保存します（端末の外には出ません）。
- ライブ映像：WebRTC ＋ PeerJS 1.5.5（jsDelivrから、必要なときだけ読み込み）。合言葉からBのIDを作り（SHA-256）、HMAC-SHA256で本人確認をしてから映像を送ります。合言葉そのものは送りません。
- 録画：ブラウザの MediaRecorder でカメラ映像をそのまま録画し（iPhoneではMP4形式）、IndexedDB に保存します。「保存・共有」は Web Share API（共有シート）を使います。
- 確認済みのこと（v5）：パソコンのブラウザ（Chromium）の2つのタブで、ライブ映像・つなぎ直し・3つの操作・動物の知らせ（帯・写真・枠）を確認しました。
- 確認済みのこと（v4）：パソコンのブラウザ（Chromium）で、写真ファイルを使って次のことを確認しました。
  - 猫・人の判定と、「来た／いない」の切り替え、通知の最短間隔
  - ntfy.sh への写真付き通知の送信と受信、自動再開に失敗したときの通知
  - 録画の開始・停止・保存・再生・削除（テストでは、カメラの代わりに読み込んだ写真を録画）
- iPhone実機（Safari）での確認、特にカメラ映像の録画・ライト・「直接つながるか」は、これから行う必要があります。
